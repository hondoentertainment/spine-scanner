# AGENTS.md

Guidance for coding agents and automated assistants working in this repository.

## Project overview

SpineScanner is a React + TypeScript progressive web app for scanning and managing a personal book library. It supports barcode scanning, spine OCR, metadata lookup, offline usage, import/export, and optional Supabase sync.

## Tech stack

- React 19, TypeScript 5, Vite 7
- Zustand, Vitest, React Testing Library, Playwright

## Local setup

```bash
npm install
npm run dev
```

Open [http://localhost:5173/spine-scanner/](http://localhost:5173/spine-scanner/) in your browser.

### Environment variables

Copy `.env.example` to `.env` and set values as needed. Never commit secrets.

| Variable | Purpose |
|----------|---------|
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | Optional cloud sync |
| `VITE_SITE_URL`, `VITE_BASE_PATH` | Production URL and base path (GitHub Pages uses `/spine-scanner/`) |
| `VITE_SUPPORT_EMAIL` | Support contact |
| `VITE_ENABLE_SCANNER_DEBUG` | Extra scanner diagnostics (`true` in prod only when debugging) |
| `VITE_AMAZON_AFFILIATE_TAG` | Optional Amazon associate tag |
| `VITE_SENTRY_DSN`, `VITE_APP_ENV`, `VITE_APP_RELEASE` | Optional Sentry monitoring |

## Validation before you finish

### Match CI (pull requests)

CI runs on every PR to `main` (see `.github/workflows/ci.yml`):

1. `npm run check:production` (with example env vars set in the workflow)
2. `npm run lint`
3. `npm run test:coverage` (uses `NODE_OPTIONS=--max-old-space-size=8192`; thresholds in `vitest.config.ts` — `src/App.tsx` is excluded from coverage because the shell is covered by E2E)
4. `npm run build`
5. Playwright Chromium smoke: `npm run test:e2e:release`

Run the same sequence locally when changing anything that could affect production config, tests, build, or core user flows.

### Deploy workflow

Pushes to `main` run `.github/workflows/deploy.yml`: `check:production`, `test:coverage`, `build`, full `test:e2e:release`, then deploy to GitHub Pages.

### OCR / scanner-heavy changes

Also run:

```bash
npm run test:integration
```

Scheduled workflow `.github/workflows/ocr-heavy.yml` runs integration tests and OCR E2E separately.

### E2E prerequisites

- `npm run build` before full Playwright suites that expect a production build
- `e2e/fixtures/book-spine-isbn.png` is generated by `npm run generate-ocr-fixture`; commit the fixture for reliable CI (see README)

## Repository map

- `src/components/` — UI (scanner, library, shelves, auth, data management)
- `src/store/` — Zustand stores
- `src/hooks/` — Scan pipeline, OCR, barcode, lookup
- `src/lib/` — Supabase client and sync
- `src/utils/` — ISBN validation, OCR helpers, import/export
- `src/test/`, `src/testing/` — Test utilities
- `e2e/` — Playwright tests and fixtures
- `scripts/` — Asset copy, PWA icons, OCR fixture, production checks, scan benchmark

```bash
npm run benchmark:scan

```

## Change guidelines

1. Keep diffs focused; avoid unrelated refactors.
2. Preserve behavior unless the task explicitly changes product behavior.
3. Prefer explicit types over `any`; follow patterns in neighboring files.
4. Add or update tests when behavior changes.
5. Do not commit secrets or local `.env` files.

## Definition of done

- Implementation complete
- Tests updated where appropriate
- `lint`, `test` (or `test:coverage` to mirror CI), and `build` pass
- `check:production` passes when env-driven code changes
- Documentation updated when setup or public behavior changes
